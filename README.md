# 层间 · 音乐练习

## 简介

层间是给跳舞的人用的听音乐工具：扒舞、复习、编舞、freestyle 都可以用。上传一段练舞视频或一首歌，app 会把音乐拆成多条音轨（人声、鼓、贝斯等），你可以只听某一层，同时画面保持同步，还能放慢速度而不变调。

它是一个网页 app，手机和电脑都能用，界面会根据屏幕宽度自动调整。整个项目没有任何 npm 依赖。

默认情况下，音轨分离在浏览器里用信号处理算法（DSP）完成，文件不会离开你的设备。如果运行服务器的电脑上装了 [Demucs](https://github.com/facebookresearch/demucs)，app 会改用 Demucs AI 分离：这时文件只上传到你自己电脑上运行的本地服务器，不会发到其他地方，处理完临时文件会被删除。

## 功能

- **上传视频或音频**：点击选择文件，电脑上也可以直接拖进页面。支持浏览器能解码的格式，例如 MP4 / MOV / WEBM / MP3 / M4A / WAV。
- **9 个音轨按钮**：原曲、纯伴奏、人声、鼓、贝斯、和声伴奏、额外打击乐、效果音、其他音效。分离完成前可以先播放原曲，分离完成后其余按钮才可点击。
- **Demucs AI 分离（可选）**：服务器检测到 Demucs 时自动使用，进度区显示“上传到本地服务器…”“排队中（第 N 位）”“AI 分离中 N%”。Demucs 不可用或服务器连不上时直接用浏览器分离；上传、任务或下载失败时也会自动改用浏览器分离，并提示原因。
- **浏览器分离按设备分档**：电脑上用高质量模式（更慢、更准），手机上用快速模式（耗时和内存与以前基本一致）。
- **取消分离**：分离进行中会出现“取消分离”按钮。取消后不会再改用浏览器分离，正在进行的 Demucs 任务会被服务器终止。重新打开这个文件会从头分离。
- **画面与音乐同步**：切换音轨时播放位置不变，画面不停。
- **变速保持音高**：0.5× / 0.75× / 1× / 1.25× / 1.5× 循环切换，音高不变。
- **循环**：整首循环播放，播到结尾自动回到开头。
- **真实分析**：显示时长、采样率、声道数、估算 BPM、分离方式（“Demucs AI（htdemucs）”或“浏览器 DSP（高质量模式 / 快速模式）”），以及每条音轨是怎么得到的。
- **音乐台**：本次打开页面期间加载过的文件列表，点一下重新打开。最近用过的文件会保留分离结果（电脑上 3 个，手机上 2 个，都包括正在练习的那个），重新打开不用再等分离，也不会再上传；更早的文件重新打开时会重新分离。为了给分离腾出内存，超出数量的旧结果在新分离开始前就会释放。刷新页面后列表和缓存都会清空。Demucs 和浏览器分离的结果按同样的规则缓存。
- **可视化**：视频文件在画面正下方显示一条横向滚动的音轨跑道，每条音轨一行，不挡画面（默认打开）；纯音频文件把 8 条音轨各画成一种图形、替换封面（默认打开）。正在听的那条最亮，见下文“可视化”。
- **我的**：设置默认速度、是否自动循环，以及 AI 分离模型：`htdemucs`（4 轨，较快，默认）或 `htdemucs_6s`（6 轨，多出吉他和钢琴）。设置保存在浏览器的 localStorage 里，改模型后从下一次新开始的分离起生效。服务器没有 Demucs 时，模型选项下面会提示“服务器未安装 Demucs，当前使用浏览器分离”。
- **电脑键盘快捷键**：

  | 按键 | 作用 |
  | --- | --- |
  | 空格 | 播放 / 暂停 |
  | ← / → | 后退 / 前进 5 秒 |
  | 1 到 9 | 按顺序选择 9 个音轨 |
  | L | 开关循环 |
  | Esc | 关闭“真实分析”面板 |

## 运行方式

需要 Node.js 18 或更高版本。不需要 `npm install`。

```bash
npm start
```

启动后终端会打印访问地址，默认端口 5173。紧接着服务器检测 Demucs，并多打印一行“AI 分离”的结果：

```
层间 · 音乐练习 已启动
  电脑访问:  http://localhost:5173
  手机访问:  http://192.168.x.x:5173  (同一 Wi-Fi 下)
  AI 分离:  已启用 Demucs（htdemucs / htdemucs_6s）
```

没有检测到 Demucs 时最后一行是 `AI 分离:  未检测到 Demucs，将使用浏览器分离`，其他功能照常可用。

- **电脑**：浏览器打开 http://localhost:5173 。
- **手机**：手机和电脑连同一个 Wi-Fi，打开终端里打印的“手机访问”地址。如果打不开，检查电脑防火墙是否允许 Node 的入站连接。
- 换端口：`PORT=8080 npm start`。服务默认监听 `0.0.0.0`，可以用 `HOST` 环境变量改成别的地址，例如 `HOST=127.0.0.1` 只允许本机访问。

### 环境变量

| 变量 | 默认值 | 作用 |
| --- | --- | --- |
| `PORT` | `5173` | 监听端口 |
| `HOST` | `0.0.0.0` | 监听地址 |
| `DEMUCS_CMD` | `demucs` | 调用 Demucs 的命令和固定参数。可以写成 JSON 字符串数组，例如 `["C:\\Python311\\python.exe","-m","demucs"]`；也可以用空白分隔，含空格的部分用双引号括起来，例如 `"C:\Program Files\Python311\python.exe" -m demucs`。无法解析时视为 Demucs 不可用 |
| `DEMUCS_MAX_UPLOAD_MB` | `2048` | AI 分离的上传大小上限（MB），正整数，填错时用默认值 |
| `DEMUCS_TIMEOUT_MIN` | `30` | 单个 Demucs 任务的超时（分钟），可以是小数，填错时用默认值 |

在 PowerShell 里设置环境变量再启动：

```powershell
$env:DEMUCS_CMD = '["C:\\Python311\\python.exe","-m","demucs"]'
npm start
```

服务器启动时会先清空临时目录，再用 `DEMUCS_CMD` 加 `--help` 运行一次来检测 Demucs，最多等 10 秒。命令不存在、退出码不是 0 或超过 10 秒都算不可用，这次运行期间就一直用浏览器分离。Windows 上第一次加载 PyTorch 可能很慢，超过 10 秒时会被误判为不可用；遇到这种情况，先在终端手动运行一次 `demucs --help`（或你配置的命令），等它跑完再重启 `npm start`。检测完成之前打开的文件也会用浏览器分离。

关于 HTTPS：部分手机浏览器的某些功能（如摄像头、Service Worker）要求 HTTPS，但本 app 只用到文件选择、媒体播放和对同一服务器的请求，通过局域网 HTTP 地址就能正常使用。

## 启用 Demucs AI 分离

Demucs 是可选的。不装也能用，只是分离效果是浏览器 DSP 的水平。

1. **安装 Demucs**（需要 Python 和 PyTorch，有 NVIDIA GPU 会快很多，没有也能用 CPU 跑）：

   ```bash
   pip install demucs
   ```

   PyTorch 如果没有被自动装上，按 [PyTorch 官网](https://pytorch.org/) 的说明选对应的版本安装。第一次分离时 Demucs 会下载模型文件，需要联网。

2. **安装 FFmpeg**：Demucs 读取 MP4 / M4A / MOV 这类压缩格式要用 FFmpeg。把 `ffmpeg` 装好并加入 PATH（在终端里能直接运行 `ffmpeg -version`）。缺少 FFmpeg 时这类文件的任务会失败，app 会显示失败原因并自动改用浏览器分离。

3. **Windows 上配置 `DEMUCS_CMD`**：服务器用 `child_process.execFile` 直接启动程序，不经过命令行解释器，所以命令必须是 `.exe`，不支持 `.cmd` / `.bat`。`pip` 装好后一般会有 `demucs.exe`（在 Python 的 `Scripts` 目录下）；如果它不在 PATH 里，或者找不到，就用 `python -m demucs`：

   ```powershell
   $env:DEMUCS_CMD = '["C:\\Python311\\python.exe","-m","demucs"]'
   ```

4. 重新运行 `npm start`，看到 `AI 分离:  已启用 Demucs` 就可以了。

### 处理流程

1. 打开文件后，app 先请求 `GET /api/separate/status`，最多等 3 秒。请求失败、超时或 Demucs 不可用时直接用浏览器分离，文件不上传。
2. Demucs 可用时，app 把文件上传到 `POST /api/separate?model=<模型>&ext=<扩展名>`，每秒查询一次任务状态。
3. 任务完成后，app 逐条下载 Demucs 输出的 WAV，在浏览器里换算成 8 条音轨（见下表），然后发送 `DELETE` 让服务器删掉结果。
4. 上传失败（包括超过大小上限、队列已满）、任务失败、下载失败时，app 改用浏览器分离并提示原因。用户点“取消分离”或打开别的文件时，app 发送 `DELETE` 并停止查询，不会改用浏览器分离。

### 接口

| 请求 | 作用 |
| --- | --- |
| `GET /api/separate/status` | 返回 `available`（是否可用）、`checking`（是否还在检测）、`models`、`maxUploadBytes`、`queueLength` |
| `POST /api/separate?model=...&ext=...` | 请求体是文件本身。成功返回 202 和 `{ id, status: "queued", position }`。Demucs 不可用 503，模型不在 `htdemucs` / `htdemucs_6s` 里 400，队列已满 429，超过上传上限 413 |
| `GET /api/separate/<id>` | 任务状态：`queued`（带排队位置 `position`）、`running`（带 0 到 100 的 `progress`）、`done`（带 `stems`）、`failed`（带 `error`）、`cancelled` |
| `GET /api/separate/<id>/<音轨名>.wav` | 下载结果，音轨名只接受该模型的输出名（如 `vocals`、`drums`） |
| `DELETE /api/separate/<id>` | 取消任务或删除结果：排队中的移出队列，运行中的终止 Demucs 进程，并删除该任务的临时文件 |

任务 ID 是服务器生成的 32 位十六进制随机数，格式不对或不存在的 ID 返回 404。

### 排队、上限和临时文件

- 同一时间只运行 1 个 Demucs 进程，其余任务按先来后到排队。上传中、排队中和运行中的任务加起来最多 4 个，第 5 个返回 429。
- 上传超过 `DEMUCS_MAX_UPLOAD_MB`（默认 2048 MB）时停止接收，删除已写入的部分并返回 413。app 自身的长度限制（见“已知限制”）在上传前就会检查。
- Demucs 运行超过 `DEMUCS_TIMEOUT_MIN`（默认 30 分钟）会被终止，任务记为失败。进度来自 Demucs 输出到标准错误的进度条百分比。
- 临时目录是 `os.tmpdir()/cengjian-demucs`（Windows 上一般是 `%TEMP%\cengjian-demucs`），每次启动服务器时清空。每个任务一个子目录，以任务 ID 命名；上传文件名是 `input.<扩展名>`，扩展名只接受 mp4、m4a、mp3、wav、aac、flac、ogg、webm、mov、mkv，其他一律存成 `.bin`。不会使用你电脑上的原文件名。
- 任务完成后立即删除上传文件，结果保留到 app 发来 `DELETE` 或 30 分钟后自动删除，以先到者为准。任务失败或取消时立即删除整个任务目录。

### Demucs 输出和按钮的对应关系

Demucs 只输出 4 轨（`htdemucs`：vocals / drums / bass / other）或 6 轨（`htdemucs_6s`：多出 guitar / piano）。额外打击乐、效果音、其他音效是 app 在浏览器里用 DSP 从 Demucs 的输出继续拆出来的。

| 按钮 | 来源 |
| --- | --- |
| 原曲 | 原文件，不变 |
| 人声 | `vocals` |
| 纯伴奏 | `drums + bass + other`（`htdemucs_6s` 再加 `guitar + piano`） |
| 鼓 | `drums` |
| 贝斯 | `bass` |
| 和声伴奏 | `other`（`htdemucs_6s` 为 `guitar + piano + other`） |
| 额外打击乐 | `drums` 经 5 kHz 高通 |
| 效果音 | `other` 的立体声两侧成分（(左 − 右) / 2）中 1.5 kHz 以上的部分，左右声道同相输出；单声道来源改取 `other` 中 6 kHz 以上的部分 |
| 其他音效 | `other` 减去效果音后的残余 |

每条音轨的峰值超过满幅时会整体压低，不会削波。“真实分析”面板会显示所用模型和每条音轨的来源。

### 安全

上传接口没有登录和访问控制，只适合在自己的电脑或自己信任的局域网里用，不要把端口暴露到公网。只想在本机用时，用 `HOST=127.0.0.1` 启动（这样手机就连不上了）。服务器只用 `execFile` 加参数数组启动 Demucs，命令行里的路径和模型名都来自服务器生成的值或允许值列表，不会拼接用户输入。

## 可视化

练习室可以把 8 条分离出来的音轨画出来，一眼看出鼓点、贝斯和人声在什么位置。视频文件画成画面下方的音轨跑道，纯音频文件画成替换封面的全画面图形。

### 开关和默认值

- 播放控制区（循环按钮旁边）有一个“可视化”按钮，按下状态用 `aria-pressed` 表示，可以用键盘聚焦和操作。
- **视频文件**：在视频画面正下方、播放控件上方显示音轨跑道，宽度和画面卡片相同，和画面没有重叠，画面上不画任何东西。默认打开。
- **纯音频文件**：画布替换原来的封面图，文件名照常显示。默认打开。
- 视频和纯音频的开关分开记，和其他设置一起保存在 localStorage 的 `cengjian.settings` 里（`visVideo` / `visAudio`）。没有保存过或保存的不是布尔值时用上面的默认值；以前保存过的值照常生效，包括以前把视频可视化关掉时存下的 `false`。
- 可视化数据准备好之前按钮不可点，旁边显示“可视化准备中…”。视频文件在计算期间跑道已经占好位置，显示为空的深色条，数据就绪后直接填入内容，播放控件不会再往下跳。数据生成失败时显示“可视化数据生成失败”，跑道不占位置，播放、分离结果和导出都不受影响。关闭时练习室的画面、控件和播放和以前完全一样。

### 音轨跑道（视频文件）

跑道的样子参考 DJ 软件的彩色波形和节奏游戏的下落轨道：

- **位置和高度**：跑道高度是画面卡片宽度的 20%，最少 112 像素、最多 160 像素（CSS `clamp(112px, 20cqw, 160px)`），背景色 `#0b0d14`。手机竖屏（375 像素宽）时是 112 像素，画面卡片 800 像素宽以上时是 160 像素。
- **每条音轨一行**：有数据的音轨各占一行，自上而下固定为鼓、额外打击乐、贝斯、人声、和声伴奏、纯伴奏、效果音、其他音效。节奏轨道在最上面，离画面最近。颜色和纯音频可视化里各层的颜色相同。
- **时间窗口**：时间从右往左滚过一条白色竖线（播放线），播放线在跑道宽度 25% 处。播放线左边是刚过去的 1 秒，右边是接下来的 3 秒，能提前看到下几个鼓点。跑道按播放器的当前播放位置画，所以放慢或加快时滚动速度跟着变，拖动进度条或循环跳回开头后下一帧就显示新位置。开头之前和结尾之后的部分是空的。
- **波形**：贝斯、人声、和声伴奏、纯伴奏画成以这一行中线为轴、上下对称的填充波形，高度随响度起伏（半高最多为行高的 0.45）。波形按固定的时间网格取样（最多 400 个点），滚动时同一时刻的波形高度不变，不会抖动。
- **鼓点标记**：鼓、额外打击乐、效果音、其他音效在一条淡波形（半高最多为行高的 0.35）上，每个起音画一个明亮的圆角竖条，高度为行高的 0.7。每行最多画 48 个标记，超过时保留离播放线最近的 48 个。标记越过播放线后的 150 毫秒内，播放线和这一行的交点处会闪一下光晕。
- **已播放部分变暗**：播放线左边的波形亮度降到 0.45 倍，标记降到 0.4 倍。
- **选中音轨更高更亮**：选中的那条音轨所在行的高度是其他每行的 3 倍（8 条时占 30%），亮度按下文“选中音轨更亮”的系数。选“原曲”或选中的音轨没有数据时所有行一样高。切换音轨后下一帧生效，没有过渡动画。
- **文字标签**：每行左侧显示中文名（10 像素字），竖直居中。行高不到 14 像素时不显示文字，只靠颜色区分。例如手机上 112 像素高、选中一条音轨时，只有选中的那一行有标签。标签只在练习室里显示，导出的视频里没有文字。

### 每条音轨的样式（纯音频文件）

| 音轨 | 样式 |
| --- | --- |
| 纯伴奏 | 背景辉光：画面中心一大片柔和的紫色径向光，亮度随纯伴奏的响度起伏 |
| 人声 | 横贯画面的暖黄色波形线，起伏幅度随人声响度变化 |
| 鼓 | 每个鼓点从画面中心扩散出一个红色发光圆环，0.6 秒内越扩越大、越来越淡，最多同时 6 个 |
| 贝斯 | 画面底部一条蓝色光带，高度和亮度随贝斯响度变化 |
| 和声伴奏 | 5 个缓慢漂移的薄荷绿色斑（漂移周期 20 到 40 秒），亮度随和声伴奏响度变化 |
| 额外打击乐 | 每次敲击从中心附近向外飞散 10 个暖白色小亮点，持续 0.4 秒 |
| 效果音 | 40 个散布的紫色粒子，亮度随响度变化，起音后 0.3 秒内更亮 |
| 其他音效 | 40 个散布的天蓝色粒子，规则同效果音 |

亮点、粒子和色斑的位置是由时间、音轨和序号算出来的，不是真正的随机，同一时刻每次画出来都一样。颜色和样式目前不能自定义，“原曲”没有单独的一层。

### 选中音轨更亮

选中一条分离出来的音轨时，它那一层按原亮度、原尺寸画，其他 7 层亮度降到 0.35、尺寸缩到 0.8。选“原曲”时 8 层一样亮，亮度 0.7、尺寸 0.9。切换音轨后下一帧就按新的音轨强调。音轨跑道用同样的亮度系数（选中 1、其余 0.35、“原曲”时全部 0.7），尺寸的变化换成上文的行高 3 倍；播放线始终是白色，不受影响。

### 减少动态效果

系统或浏览器开启“减少动态效果”（`prefers-reduced-motion: reduce`）时：

- 纯音频的全画面可视化：图形的位置和大小固定不动，只有亮度变化。亮度取前 300 毫秒响度的平均值，变化很平缓，没有闪烁和飞散。
- 音轨跑道：照常滚动（滚动本身就是信息），只去掉播放线处的闪光。其余图形的亮度本来就不随时间变化。

这个设置随时改随时生效，只影响练习室里的实时显示，导出的视频一律用完整动效（包括闪光）。

### 和播放同步

画面只根据播放器的当前播放位置计算，所以放慢、变速、拖动进度条和循环跳回开头时都和声音对齐。播放中每个动画帧画一次；暂停时只在播放位置、选中音轨、画布大小或开关变化时重画；页面切到后台或可视化关闭时完全不画。视频文件只画跑道，封面画布不画；纯音频文件只画封面画布。画布像素按显示尺寸乘设备像素比，设备像素比最多按 2 算。

### 数据从哪来

播放器同一时间只播放一条音轨，其他 7 条没有声音可以实时分析，所以 app 在分离完成后（或打开有分离缓存、但还没有可视化数据的文件时）预先计算可视化数据。可视化开关关着也会算，打开时马上能用。

- 对每条音轨算出每 10 毫秒一个的响度（0 到 255，按这条音轨自己的最大响度归一化，几乎没声音的音轨全为 0），鼓、额外打击乐、效果音、其他音效再找出起音时间（两次起音至少相隔 50 毫秒）。
- 计算在 Web Worker 里进行，一次只读取并分析一条音轨；浏览器不支持模块 Worker 时改在主线程逐条计算，每条之间让出主线程。某条音轨读不出来就跳过它，其余照常显示。
- 数据存在这个文件的分离缓存里，每条音轨每 10 毫秒 1 字节，3 分钟的歌 8 条合计约 140 KB。再次打开同一个文件直接复用，不重新计算。音乐台缓存释放这个文件的分离结果时，可视化数据一起释放。
- 计算过程中打开别的文件或取消分离，计算会停止，算了一半的结果丢弃。

## 导出

练习室的音轨区有一个“导出”按钮，可以把一条分离出来的音轨存成文件，拿去剪辑或分享练舞素材。

### 用法

- 分离完成、选中一条已生成的音轨（纯伴奏、人声、鼓等 8 条之一）时，“导出”按钮才能点。分离进行中或导出进行中按钮不可用。
- 选中“原曲”时按钮不可用，旁边提示“原曲就是原文件，无需导出”。
- 导出的是**点击“导出”那一刻选中的音轨**。导出过程中切换音轨，不会改变这次导出的内容和文件名。
- 视频文件点“导出”后弹出选择：“导出视频”“只导出音频（WAV）”“取消”。可视化数据准备好以后，“导出视频”下面多一项“导出视频（带可视化）”。
- 纯音频文件没有画面。可视化数据准备好时，点“导出”弹出“可视化视频”“只导出音频（WAV）”“取消”（没有“导出视频”）；还没准备好或生成失败时，和以前一样直接保存 WAV，不弹选择。
- **只导出音频（WAV）**：直接保存播放用的那份 WAV，内容逐字节相同，全程在浏览器里完成，不访问服务器。
- **导出视频**：原视频的画面配上选中的音轨，原来的声音被替换掉。导出总是 1 倍速、完整长度，和当前的播放速度、位置、循环设置无关。
- 视频导出进行中会显示进度和“取消导出”按钮。取消后显示“已取消导出”，不会下载任何文件。导出中打开别的文件也会取消导出。
- 文件名是 `<原文件名去掉扩展名>-<音轨名>.<扩展名>`，例如 `练习 v2.final-人声.mp4`。`\ / : * ? " < > |` 和控制字符换成 `_`，首尾的空格和句点去掉，名字为空时用“导出”，文件名主体最多 80 个字符（截短原文件名部分，保留 `-<音轨名>`）。文件名只在浏览器里使用，不会发给服务器。

### 两条视频导出路径

1. **服务器端 FFmpeg 合成（首选）**：app 先请求 `GET /api/export/status`，最多等 3 秒。FFmpeg 可用时，把音轨 WAV 和原文件上传到本地服务器，进度区依次显示“上传到本地服务器…”“排队中（第 N 位）”“合成视频 N%”（读不出时长时显示“合成视频中…”）和“下载视频…”。合成结果是 MP4，下载完 app 发送 `DELETE` 让服务器删掉结果。
2. **浏览器实时录制（回退）**：服务器没有 FFmpeg、服务器连不上，或者 FFmpeg 路径中途失败时，浏览器用 `captureStream` + `MediaRecorder` 从头到尾按 1 倍速播放一遍并录下来，输出 WEBM（依次尝试 `video/webm;codecs=vp9,opus`、`video/webm;codecs=vp8,opus`、`video/webm`）。

中途失败包括：上传失败（413 超过上限、429 队列已满、500 服务器写盘失败如磁盘已满、503 FFmpeg 不可用、网络错误）、任务失败（FFmpeg 报错、超时、没有画面、连续 5 次查询不到状态）和下载结果失败。这时 app 显示失败原因和“改用浏览器录制”的提示，然后自动开始录制。用户自己点“取消导出”时不会改用录制。

浏览器录制的限制：

- **耗时和视频一样长**：录制是实时播放，10 分钟的视频要录 10 分钟。进度区显示“浏览器录制中 N%（需要和视频一样长的时间）”。
- 录制期间播放、暂停、拖动进度、变速、循环、音轨按钮和快捷键都不可用；录制结束（完成、取消或失败）后恢复成录制前的音轨、位置、速度、播放状态和循环设置。服务器合成期间这些操作照常可用。
- **iOS Safari 不支持**：浏览器没有 `captureStream`（含 `mozCaptureStream`）或 `MediaRecorder`，或者不支持上面任何一种 WEBM 类型时，会提示“当前浏览器无法导出视频，可以选择只导出音频（WAV）”，并给出 WAV 导出按钮。想在 iPhone 上导出视频，需要运行服务器的电脑装好 FFmpeg。
- 浏览器阻止自动播放时会提示“浏览器阻止了播放，请再点一次导出”。

### 安装 FFmpeg

视频导出的服务器端合成需要 FFmpeg，不装也能用浏览器录制。Demucs 读取压缩格式用的也是同一个 FFmpeg（见上文），装一次即可。

1. 安装 FFmpeg 并加入 PATH，在终端里能直接运行 `ffmpeg -version`。
2. 不在 PATH 里时用 `FFMPEG_CMD` 指定。服务器用 `execFile` / `spawn` 直接启动程序，不经过命令行解释器，Windows 上必须是 `.exe`：

   ```powershell
   $env:FFMPEG_CMD = '["C:\\ffmpeg\\bin\\ffmpeg.exe"]'
   npm start
   ```

3. 启动后终端多打印一行 `视频导出: 已启用 FFmpeg`。检测失败时是 `视频导出: 未检测到 FFmpeg（原因），将使用浏览器录制`，其他功能照常可用。

服务器启动时用 `FFMPEG_CMD` 加 `-version` 运行一次检测，最多等 10 秒。命令不存在、退出码不是 0、超时或 `FFMPEG_CMD` 无法解析都算不可用，这次运行期间视频导出一直用浏览器录制。

| 变量 | 默认值 | 作用 |
| --- | --- | --- |
| `FFMPEG_CMD` | `ffmpeg` | 调用 FFmpeg 的命令和固定参数，写法和 `DEMUCS_CMD` 相同（JSON 字符串数组，或用空白分隔、含空格的部分用双引号括起来）。无法解析时视为 FFmpeg 不可用 |
| `EXPORT_MAX_UPLOAD_MB` | `10240`（10 GB） | 视频导出的上传大小上限（MB），原文件和音轨 WAV 合计，正整数，填错时用默认值 |
| `EXPORT_TIMEOUT_MIN` | `30` | 单个导出任务的超时（分钟），从任务开始运行算起，包括读取原文件信息和合成两步，可以是小数，填错时用默认值 |

### 合成规则

- 输出一律是 MP4，包含原文件的第一条画面流（跳过封面图）和上传的音轨，不包含原文件原来的声音。
- 画面是 H.264 或 HEVC 时直接复制，不重新编码，画质不变，通常几秒到几十秒就完成。VP8、VP9、AV1、MPEG-4 Part 2 等其他编码重新编码为 H.264（`libx264`，`-preset veryfast`，`-crf 20`，`yuv420p`），长视频在 CPU 上可能要比较久。
- 音频编码为 192 kbps 的 AAC。
- 输出时长等于 FFmpeg 读出的原视频时长：音轨比画面短时用静音补齐（`apad` 加 `-t <时长>`）。读不出时长时在画面结束处结束（`-shortest`），进度显示为未知。
- MP4 的索引放在文件开头（`-movflags +faststart`），播放器不用读完整个文件就能开始播放。
- 原文件里找不到画面时任务失败，原因是“文件里没有画面”。FFmpeg 以非 0 退出码结束时，失败原因取它标准错误输出的最后一行（最多 200 个字符）。超过 `EXPORT_TIMEOUT_MIN` 时终止 FFmpeg，原因是“合成视频超过 N 分钟未完成，已终止”。

**HEVC 播放兼容性**：HEVC 画面是原样复制的，会标记为 `hvc1`，Apple 设备（QuickTime、iPhone 相册）可以直接播放。但 Windows 上部分播放器和浏览器需要额外安装 HEVC 解码扩展才能播放，播不了时可以换用 VLC 之类自带解码器的播放器。这是原视频编码本身的限制，导出不会把 HEVC 转成 H.264。（带可视化的导出例外，见下一节，它总是重新编码成 H.264。）

### 带可视化的视频导出

选“导出视频（带可视化）”（视频文件）或“可视化视频”（纯音频文件）时，导出的视频里带上可视化。视频文件是上下叠放的版式：原画面完整地放在上面，音轨跑道放在下面，两者不重叠，跑道不会遮住画面。因为下面多了一条跑道，导出视频的尺寸比原视频高，横屏视频导出后也不是 16:9。导出视频里的跑道没有文字标签，各行只靠颜色和顺序区分。纯音频文件是全画面可视化。被强调的是导出的那条音轨（和练习时选中它的样子一样），而且一律用完整动效，不受“减少动态效果”影响。文件名是 `<原文件名去掉扩展名>-<音轨名>-可视化.<扩展名>`，例如 `练习-人声-可视化.mp4`，清理规则和上面相同。导出总是 1 倍速、完整长度，进度和“取消导出”按钮和普通视频导出一样。

也有两条路径：

1. **服务器快速渲染（首选，需要本地 FFmpeg）**：app 把音轨 WAV、可视化数据和原文件一起上传到本地服务器（纯音频文件也上传原文件，服务器用它读出时长）。服务器用纯 JS 的软件光栅化器逐帧画出可视化（视频文件只画跑道），通过标准输入把原始像素送给 FFmpeg，编码成 H.264 MP4。进度区显示“渲染可视化视频 N%”（读不出时长时为“渲染可视化视频中…”）。渲染比实时快，不用等整首歌放完。
2. **浏览器实时录制（回退）**：服务器连不上、没有 FFmpeg，或者上传、任务、下载失败时，和普通视频导出一样显示失败原因和“改用浏览器录制”的提示，然后在浏览器里画出和服务器渲染相同的版式，按 1 倍速实时录成 WEBM，30 fps。视频文件：录制画布上方是视频画面（按原比例放进画面区域，不足的地方是黑边），下方是跑道，尺寸按下面服务器的规则计算，只是把 1920 换成 1280（宽和总高都不超过 1280），例如 1920×1080 的视频录成 1280×976（画面 1280×720 + 跑道 256）。纯音频文件：1280×720，`#0b0d14` 深色背景上画可视化。耗时和视频一样长，录制期间控件锁定，结束后恢复，规则和普通录制相同。浏览器不支持画布的 `captureStream`、`MediaRecorder`（含上面的 WEBM 类型）或 `AudioContext` 时，提示“当前浏览器无法导出视频，可以选择只导出音频（WAV）”并给出 WAV 导出按钮。

服务器渲染的规则：

- **视频文件的输出尺寸**：由画面的显示尺寸（竖屏视频按旋转后的尺寸算）算出输出宽度 OW、画面高度 PH 和跑道高度 SH，三者都是偶数。跑道高度 `SH = max(96, 偶数(round(0.2 × OW)))`，输出宽度不超过 1920，画面高度加跑道高度不超过 1920，画面按原宽高比缩小、不放大。输出是 OW×(PH + SH)，不是 16:9。例如：

  | 原画面 | 输出 | 画面 | 跑道 |
  | --- | --- | --- | --- |
  | 1920×1080（横屏） | 1920×1464 | 1920×1080 | 1920×384 |
  | 1080×1920（竖屏） | 970×1918 | 970×1724 | 970×194 |
  | 读不出尺寸 | 1280×976 | 1280×720 | 1280×256 |

  读不出画面尺寸时按 1280×720 的画面计算，原画面按比例放进画面区域、四周补黑边。
- **视频文件的合成**：服务器只渲染跑道的帧，渲染宽度是 OW 和 960 中较小的那个（取偶数），高度按比例取偶数，例如 1920 宽的输出按 960×192 渲染。FFmpeg 把原画面缩放、补边到 OW×PH，把跑道帧放大到 OW×SH，再用 `vstack` 上下拼接。画面和跑道不做任何混合，画面的颜色和亮度和原视频一样。
- **纯音频文件**：按 640×360 渲染全画面可视化，由 FFmpeg 放大到 1280×720，`#0b0d14` 深色背景上只有可视化。
- 帧率固定 30 fps，共渲染 `ceil(时长 × 30)` 帧，第 k 帧画的是 `k / 30` 秒时的样子。原视频的帧率也会被换成 30 fps，60 fps 的视频带可视化导出后是 30 fps。
- 画面总是重新编码（`libx264`，`-preset veryfast`，`-crf 20`，`yuv420p`），H.264 / HEVC 原视频也不再直接复制，所以比普通视频导出慢一些，画质会有轻微损失。音频和普通导出一样是 192 kbps 的 AAC，用静音补齐，用 `-t <时长>` 截到原文件时长（读不出时长时用可视化数据里的时长），带 `-movflags +faststart`，不包含原文件原来的声音。
- `layout=stacked` 时原文件里找不到画面，任务失败，原因是“文件里没有画面”。FFmpeg 在所有帧写完之前退出时任务失败：退出码不是 0 时原因取它标准错误的最后一行，退出码是 0 时原因是“FFmpeg 提前结束”。
- 服务器每渲染一帧都让出一次事件循环，FFmpeg 处理不过来时暂停渲染，渲染期间照常响应状态查询和静态文件请求。
- 可视化导出任务和普通视频导出共用同一个队列、4 个名额、单进程、`EXPORT_TIMEOUT_MIN` 超时、`EXPORT_MAX_UPLOAD_MB` 上限、临时目录和清理规则。可视化数据只保存在内存里，不写入磁盘，任务结束时释放。

### 接口

| 请求 | 作用 |
| --- | --- |
| `GET /api/export/status` | 返回 `available`（FFmpeg 是否可用）、`checking`（是否还在检测）、`maxUploadBytes`、`queueLength` |
| `POST /api/export?ext=<扩展名>&wavBytes=<WAV 字节数>` | 请求体是音轨 WAV 紧接着原文件，用 `wavBytes` 切分。成功返回 202 和 `{ id, status: "queued", position }`。FFmpeg 不可用 503（不写文件）；缺少或不支持的扩展名、`wavBytes` 无效、缺少原文件、WAV 不完整或不是 RIFF/WAVE 格式 400；未完成任务已满 429（不写文件）；超过上传上限 413；建任务目录或写入上传文件失败（如磁盘已满）500，错误信息“服务器无法保存上传文件”。出错时已写入的文件都会删除 |
| `GET /api/export/<id>` | 任务状态：`queued`（带排队位置 `position`）、`running`（带 0 到 100 的 `progress`，进度未知时为 `null`）、`done`、`failed`（带 `error`）、`cancelled` |
| `GET /api/export/<id>/result.mp4` | 下载结果，`Content-Type: video/mp4`。任务未完成时 404 |
| `DELETE /api/export/<id>` | 取消任务或删除结果，返回 204：上传中的停止接收，排队中的移出队列，运行中的终止 FFmpeg 进程，并删除该任务的全部临时文件 |

带可视化的导出用同一个上传接口，多两个参数：`POST /api/export?ext=<扩展名>&wavBytes=<n>&visBytes=<m>&layout=<stacked|standalone>`。请求体依次是音轨 WAV（n 字节）、可视化数据 JSON（m 字节）和原文件。视频文件用 `layout=stacked`（画面在上、跑道在下），纯音频文件用 `layout=standalone`。原来给视频文件用的 `layout=overlay` 已经删除，不再作为别名接受，会返回 400 “可视化布局参数无效”。可视化数据里只有音轨 id、数值和 Base64 编码的响度数据，加上要强调的音轨 id，不包含文件名。两个参数都不带时，请求按上表处理，和以前完全一样。参数和数据的 400 规则：

| 情况 | 错误信息 | 文件 |
| --- | --- | --- |
| 只有 `visBytes` 和 `layout` 其中之一 | 可视化参数不完整 | 不写文件 |
| `visBytes` 不是十进制整数，或不在 2 到 16777216（16 MB）之间 | 可视化数据大小参数无效 | 不写文件 |
| `layout` 不是 `stacked` 或 `standalone`（区分大小写，`overlay` 也算无效） | 可视化布局参数无效 | 不写文件 |
| 声明的 `Content-Length` 不超过 WAV 加可视化数据的长度，或请求体在原文件之前正好结束 | 缺少原文件 | 删除已写入的文件 |
| 请求体在可视化数据中途结束 | 可视化数据不完整 | 删除已写入的文件 |
| 可视化数据不是合法的 UTF-8 JSON，或格式不对（版本、帧率、时长超过 3600 秒、音轨 id、响度数据长度、起音时间的顺序和范围、强调的音轨 id） | 可视化数据无效 | 删除已写入的文件 |

其余规则（503、429、413、500，`ext` / `wavBytes` 校验和 WAV 格式检查）和普通导出相同，413 按 WAV、可视化数据和原文件的总字节数计算。

`ext` 只接受和 AI 分离相同的扩展名（mp4、m4a、mp3、wav、aac、flac、ogg、webm、mov、mkv）；文件名没有这些扩展名时，app 按文件类型推断，推断不出就用 mp4。FFmpeg 按内容识别格式，扩展名只用来给临时文件命名。任务 ID 是服务器生成的 32 位十六进制随机数，格式不对或不存在的 ID 返回 404，其他请求方法返回 405。

### 排队、上限和临时文件

- 同一时间只运行 1 个 FFmpeg 合成进程，其余任务按先来后到排队。上传中、排队中和运行中的任务加起来最多 4 个，第 5 个返回 429。视频导出和 AI 分离各有各的队列，互不占用名额。
- 上传超过 `EXPORT_MAX_UPLOAD_MB`（默认 10240 MB）时停止接收，删除已写入的部分并返回 413。上传中途断开时同样删除已写入的文件并释放名额。
- 临时目录是 `os.tmpdir()/cengjian-export`（Windows 上一般是 `%TEMP%\cengjian-export`），每次启动服务器时清空。每个任务一个子目录，以任务 ID 命名，里面只有 `audio.wav`、`input.<扩展名>` 和 `output.mp4`，不会使用你电脑上的原文件名。
- 任务完成后立即删除两个上传文件，只留 MP4 结果，保留到 app 发来 `DELETE` 或 30 分钟后自动删除，以先到者为准。
- 任务失败或取消时立即删除整个任务目录，任务状态再保留 5 分钟供 app 查询。

接口的安全说明和 AI 分离相同：没有登录和访问控制，只在自己的电脑或信任的局域网里用。FFmpeg 只通过 `execFile` / `spawn` 加参数数组启动，不经过 shell，命令行里的路径只由临时目录、任务 ID 和允许的扩展名拼成。

- 浏览器报告的 `currentTime` 精度较粗时，速度微调会不会来回切换（快了又慢、慢了又快）。0.04 / 0.01 秒和 5% 这几个值目前只在模拟元素上测过，如果真机上有问题，可以在 `public/js/player.js` 的 `DRIFT` 里调整。

## 音轨分离原理

这一节说的是浏览器 DSP 分离。用 Demucs 时的做法见上文“Demucs 输出和按钮的对应关系”。

**先说清楚：这是传统信号处理（DSP）做的近似分离，不是 AI 模型。** 效果明显不如 Demucs 这类深度学习模型，尤其是人声、和声伴奏、效果音、其他音效这几条，会互相串音。鼓和贝斯通常最可用，适合扒节奏和找重拍。

### 处理流程

1. 浏览器用 `OfflineAudioContext` 把文件的音轨解码成 44.1 kHz 的 PCM 数据。
2. 在 Web Worker 里对左右声道做分段 STFT（Hann 窗），对每个时频点算出几种线索：
   - **HPSS 软掩码**：对幅度谱分别做时间方向和频率方向的中值滤波，把声音分成谐波（持续的音高）、打击（短促的瞬态）和残余三部分。
   - **相位感知的中置掩码**：比较左右声道的幅度和相位，左右同相、几乎一样的成分视为“中置”，人声通常混在中间。同一个时频点上左右相位相反的成分算作两侧，不会被误当成中置。
   - **自适应贝斯交叉点**：按每一帧低音的音高，在约 150 到 320 Hz 之间决定贝斯和其他谐波的分界，不再用固定的 250 Hz。
3. 用这些线索把每个时频点分成 7 份“原子”：人声、贝斯、其他谐波、低频打击、高频打击、两侧效果、残余。每个点上 7 份的比例都不小于 0、加起来等于 1，所以各原子相加就是原曲，不会凭空多出或丢掉声音。所有频率划分都在频谱里完成，不再做时域滤波和相减。
4. 由原子组合出 8 条音轨（见下表），每条编码成 WAV。和以前一样，偏安静的音轨会适当放大（最多 4 倍）方便练习，峰值超过满幅时整体压低，不会削波。

两种模式的区别：

- **快速模式（手机）**：一次 STFT（窗长 2048，跳步 512），HPSS 用 13×13 的中值滤波和 1.5 的边界系数，和以前的参数相同，耗时和内存也和以前基本一致。
- **高质量模式（电脑）**：两级处理。
  - 第一级用长窗（窗长 4096，跳步 1024），频率分辨率更高，HPSS（时间 17、频率 25，边界系数 2）先分出谐波。人声除了要求中置，还看音高有没有波动：把谐波和约 1.5 秒的长时间中值比较，唱歌时音高起伏、颤音明显，而和弦铺底比较平稳。单声道文件没有中置线索，只看音高波动。
  - 第二级对第一级剩下的非谐波部分用短窗（窗长 1024，跳步 256）再做一次 HPSS（时间 45、频率 9，边界系数 2），时间分辨率更高，分出鼓、额外打击乐、效果音和其他音效。
  - 每一级最后做一次维纳细化，按各原子在相邻时频点（前后 1 帧、上下 1 个频点）上的能量比例重新分配每个时频点，减少串音，比例之和仍然是 1。

浏览器不支持模块 Worker（Worker 启动失败）时，会改在主线程分离，界面可能稍卡。Worker 已经启动后如果分离出错（例如内存不足），会直接显示错误，不会在主线程重跑一遍。两种模式都可以取消。

### 9 条音轨分别怎么来

| 音轨 | 快速模式 | 高质量模式 |
| --- | --- | --- |
| 原曲 | 上传文件自带的原始音频，不做处理，由视频（或音频）元素本身播放 | 同左 |
| 人声 | 2048 点谐波中左右同相、偏中置的 160 Hz 到 8 kHz 成分（160 到 260 Hz 渐入，5 kHz 以上渐出）；单声道取频带内全部谐波 | 4096 点谐波中左右同相、偏中置、音高有波动的同一频段成分；单声道只看音高波动 |
| 纯伴奏 | 原曲减去人声，等于其余原子之和，底鼓和贝斯保留 | 同左 |
| 鼓 | 打击部分（低频打击 + 高频打击），不含两侧高频效果 | 第一级谐波以外的部分再用 1024 点分出的打击部分，不含两侧高频效果 |
| 贝斯 | 谐波中自适应交叉点（约 150 到 320 Hz）以下的部分 | 4096 点谐波中自适应交叉点以下的部分 |
| 和声伴奏 | 谐波去掉人声和贝斯后的和弦、铺底、和声 | 同左（4096 点） |
| 额外打击乐 | 打击部分里约 6 kHz 以上（6.8 kHz 处各占一半）：镲、沙锤、拍手 | 同左（1024 点） |
| 效果音 | 1.7 kHz 以上的立体声两侧打击与残余 | 1.5 kHz 以上的立体声两侧打击与残余（1024 点） |
| 其他音效 | 既非旋律也非打击、且不属于效果音的残余 | 同左，另含第一级漏下的弱谐波 |

效果音取两侧成分的 (左 − 右) / 2，左右声道同相输出，所以手机单喇叭、单只耳机和系统“单声道音频”模式下也听得到（代价是失去宽度感）。单声道文件改用 6 kHz 以上的残余（扫频、噪声上升音），两种模式相同。

单声道文件没有左右差异，人声只能靠频段（快速模式）或音高波动（高质量模式）来分，人声和纯伴奏的区分会更差。

“真实分析”面板显示的每条音轨说明和当前使用的模式对应（`public/js/separator.js` 里的 `STEM_NOTES_BY_MODE`）。

BPM 用起音能量的自相关估算，范围 60 到 200 BPM，结果偏向 120 附近。

### 播放同步

- 视频元素（纯音频文件则是一个隐藏的 `<audio>`）是主时钟，同时负责播放“原曲”。
- 其余 8 条音轨各是一个 `<audio>` 元素，播放 WAV Blob，开启 `preservesPitch`，所以变速不变调。Demucs 和浏览器分离的结果都以同样的 WAV Blob 交给播放器。
- 同一时间只播放选中的那一条，其它暂停，这样对 iOS 更友好。切换时会等新音轨开始播放后再停掉旧的，避免出现空白。
- 播放中音轨和主时钟相差超过 0.04 秒时，把音轨的播放速度临时调快或调慢 5%（音高不变，听不出来），差距缩小到 0.01 秒以内再恢复。只有相差超过 0.25 秒（例如卡顿后）才直接跳转对齐，最多每 400 毫秒一次，因为每次跳转都会有很短的断音。拖动进度条后也会立即对齐。
- 循环开启时，在结尾前约 60 毫秒跳回开头。

## 已知限制

- **浏览器分离没有 ffmpeg**：浏览器分离只能处理浏览器自己能解码的音频编码。比如某些 MOV 里的音频编码或 Windows 上的 HEVC 视频可能无法解码，会提示失败。Demucs 读取压缩格式需要服务器所在电脑装好 FFmpeg（见上文）。
- **耗时**：一首 3 分钟的立体声歌曲，旧算法在开发机的 Node 环境里分离约 26 秒。快速模式和它差不多，手机上大概要 1 到 2 分钟；电脑上的高质量模式约为它的 2 倍。Demucs 在 CPU 上处理一首歌通常要几分钟，有 GPU 会快很多。
- **内存和长度限制**：旧算法处理 3 分钟歌曲时峰值约 800 MB，两种新模式实测都不超过它。为了避免手机浏览器因内存不足直接刷新页面，手机（触屏设备）上超过 6 分钟或 500 MB 的文件、电脑上超过 15 分钟或 2 GB 的文件会跳过音轨分离并给出提示，原曲照常播放。这个限制对 Demucs 分离同样适用，因为结果要在浏览器里换算和保存。时长先从视频（或音频）元素的元数据读取，超长的文件在读入内存和上传之前就会被拦下；读不到时长的文件在解码或下载结果后再检查一次。练舞建议先剪成需要的片段。
- **iOS 需要先点一下**：iOS Safari 只允许在用户点击后开始播放，所以打开文件后需要手动点播放。
- **循环是整首循环**：目前没有 A-B 区间循环。
- **分离质量**：浏览器分离仍然是 DSP 近似，改进后串音少了一些，但人声相关的音轨依然不干净。上面的 SDR 提升是在合成信号上测的，真实歌曲效果不一定同样明显。想要更好的效果请启用 Demucs。
- **Windows 上的测试命令**：在 Windows 上用 Node 18 / 20 时，`node --test tests/*.test.mjs` 里的通配符可能不会被展开，导致找不到测试文件。用 Node 21 或更高版本，或者把文件逐个列出来，例如 `node --test tests/dsp.test.mjs tests/separator.test.mjs`。
