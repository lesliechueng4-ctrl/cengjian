# 层间 · 音乐练习

## 简介

层间是给跳舞的人用的听音乐工具：扒舞、复习、编舞、freestyle 都可以用。上传一段练舞视频或一首歌，app 会把音乐拆成多条音轨（人声、鼓、贝斯等），你可以只听某一层，同时画面保持同步，还能放慢速度而不变调。

它是一个网页 app，手机和电脑都能用，界面会根据屏幕宽度自动调整。整个项目没有任何 npm 依赖，音轨分离完全在浏览器里完成，文件不会上传到任何服务器。

## 功能

- **上传视频或音频**：点击选择文件，电脑上也可以直接拖进页面。支持浏览器能解码的格式，例如 MP4 / MOV / WEBM / MP3 / M4A / WAV。
- **9 个音轨按钮**：原曲、纯伴奏、人声、鼓、贝斯、和声伴奏、额外打击乐、效果音、其他音效。分离完成前可以先播放原曲，分离完成后按钮才可点击。
- **画面与音乐同步**：切换音轨时播放位置不变，画面不停。
- **变速保持音高**：0.5× / 0.75× / 1× / 1.25× / 1.5× 循环切换，音高不变。
- **循环**：整首循环播放，播到结尾自动回到开头。
- **真实分析**：显示时长、采样率、声道数、估算 BPM，以及每条音轨是怎么得到的。
- **音乐台**：本次打开页面期间加载过的文件列表，点一下重新打开。最近用过的 3 个文件会保留分离结果，重新打开不用再等分离；更早的文件重新打开时会重新分离。刷新页面后列表和缓存都会清空。
- **我的**：设置默认速度和是否自动循环，保存在浏览器的 localStorage 里。
- **电脑键盘快捷键**：

  | 按键 | 作用 |
  | --- | --- |
  | 空格 | 播放 / 暂停 |
  | ← / → | 后退 / 前进 5 秒 |
  | 1 到 9 | 按顺序选择 9 个音轨 |
  | L | 开关循环 |
  | Esc | 关闭“真实分析”面板 |

## 运行方式

需要 Node.js 18 或更高版本。不需要 `npm install`。

```bash
npm start
```

启动后终端会打印访问地址，默认端口 5173：

```
层间 · 音乐练习 已启动
  电脑访问:  http://localhost:5173
  手机访问:  http://192.168.x.x:5173  (同一 Wi-Fi 下)
```

- **电脑**：浏览器打开 http://localhost:5173 。
- **手机**：手机和电脑连同一个 Wi-Fi，打开终端里打印的“手机访问”地址。如果打不开，检查电脑防火墙是否允许 Node 的入站连接。
- 换端口：`PORT=8080 npm start`。服务默认监听 `0.0.0.0`，可以用 `HOST` 环境变量改成别的地址，例如 `HOST=127.0.0.1` 只允许本机访问。

关于 HTTPS：部分手机浏览器的某些功能（如摄像头、Service Worker）要求 HTTPS，但本 app 只用到文件选择和媒体播放，通过局域网 HTTP 地址就能正常使用。

## 测试

```bash
npm test
```

实际执行的是 `node --test tests/*.test.mjs`，覆盖：

- DSP 算法：FFT、STFT、滤波、中置消除、HPSS、BPM 估算，效果音在单声道下不会抵消，文件大小和时长限制。
- 分离调度：Web Worker 启动失败时改在主线程运行，启动后出错直接报错，取消。
- 同步播放器（用假的媒体元素）：切换音轨不丢位置且无空白、变速保持音高、漂移校正、循环。
- WAV 编码和静态服务器（MIME 类型、路径穿越拦截、404）。

测试环境没有真实浏览器，iOS Safari 和 Android Chrome 上的实际播放效果（尤其是 0.5× 和 1.5× 时的同步）需要在真机上手动确认。

## 音轨分离原理

**先说清楚：这是传统信号处理（DSP）做的近似分离，不是 AI 模型。** 效果明显不如 Demucs 这类深度学习模型，尤其是人声、和声伴奏、效果音、其他音效这几条，会互相串音。鼓和贝斯通常最可用，适合扒节奏和找重拍。

### 处理流程

1. 浏览器用 `OfflineAudioContext` 把文件的音轨解码成 44.1 kHz 的 PCM 数据。
2. 在 Web Worker 里对左右声道做一次分段 STFT（窗长 2048，跳步 512，Hann 窗），对每个时频点计算两类掩码：
   - **HPSS 软掩码**：对幅度谱分别做时间方向和频率方向的中值滤波（13×13，带 1.5 的边界系数），把声音分成谐波（持续的音高）、打击（短促的瞬态）和残余三部分。
   - **中置掩码**：比较左右声道的相似度（Avendano 方法），左右几乎一样的成分视为“中置”，人声通常混在中间。
3. 用零相位的时域滤波把这些部分组合成 9 条音轨，每条编码成 WAV。

浏览器不支持模块 Worker（Worker 启动失败）时，会改在主线程分离，界面可能稍卡。Worker 已经启动后如果分离出错（例如内存不足），会直接显示错误，不会在主线程重跑一遍。

### 9 条音轨分别怎么来

| 音轨 | 做法 |
| --- | --- |
| 原曲 | 上传文件自带的原始音频，不做处理，由视频（或音频）元素本身播放 |
| 人声 | 中置 + 谐波成分，限制在 120 Hz 到 8 kHz 的人声频段 |
| 纯伴奏 | 原曲减去人声估计（中置消除）。人声估计不含 120 Hz 以下，所以底鼓和贝斯保留 |
| 鼓 | HPSS 的打击部分 |
| 贝斯 | 谐波部分经 250 Hz 四阶低通 |
| 和声伴奏 | 谐波部分减去贝斯和人声：和弦、铺底、和声 |
| 额外打击乐 | 打击部分中 5 kHz 以上的高频：镲、沙锤、拍手 |
| 效果音 | 残余和打击部分在 1.5 kHz 以上的立体声两侧成分，左右声道同相输出，所以手机单喇叭、单只耳机和系统“单声道音频”模式下也听得到（代价是失去宽度感）；单声道文件改用 6 kHz 以上的残余（扫频、噪声上升音） |
| 其他音效 | HPSS 残余：既不明显是旋律也不明显是打击的部分 |

单声道文件没有左右差异，会跳过中置掩码，所有成分都当作中置处理，因此人声和纯伴奏的区分会更差。

BPM 用起音能量的自相关估算，范围 60 到 200 BPM，结果偏向 120 附近。

### 播放同步

- 视频元素（纯音频文件则是一个隐藏的 `<audio>`）是主时钟，同时负责播放“原曲”。
- 其余 8 条音轨各是一个 `<audio>` 元素，播放 WAV Blob，开启 `preservesPitch`，所以变速不变调。
- 同一时间只播放选中的那一条，其它暂停，这样对 iOS 更友好。切换时会等新音轨开始播放后再停掉旧的，避免出现空白。
- 播放中音轨和主时钟相差超过 0.04 秒时，把音轨的播放速度临时调快或调慢 5%（音高不变，听不出来），差距缩小到 0.01 秒以内再恢复。只有相差超过 0.25 秒（例如卡顿后）才直接跳转对齐，最多每 400 毫秒一次，因为每次跳转都会有很短的断音。拖动进度条后也会立即对齐。
- 循环开启时，在结尾前约 60 毫秒跳回开头。

## 已知限制

- **没有 ffmpeg**：只能处理浏览器自己能解码的音频编码。比如某些 MOV 里的音频编码或 Windows 上的 HEVC 视频可能无法解码，会提示失败。
- **耗时**：一首 3 分钟的立体声歌曲，在开发机的 Node 环境里分离约 26 秒，手机上大概要 1 到 2 分钟。
- **内存和长度限制**：3 分钟歌曲处理时峰值约 800 MB。为了避免手机浏览器因内存不足直接刷新页面，手机（触屏设备）上超过 6 分钟或 500 MB 的文件、电脑上超过 15 分钟或 2 GB 的文件会跳过音轨分离并给出提示，原曲照常播放。练舞建议先剪成需要的片段。
- **iOS 需要先点一下**：iOS Safari 只允许在用户点击后开始播放，所以打开文件后需要手动点播放。
- **循环是整首循环**：目前没有 A-B 区间循环。
- **分离质量**：见上文，DSP 近似效果有限，人声相关的音轨尤其不干净。

## 接入真实 AI 分离（Demucs）

如果想要接近专业的分离效果，可以在服务器端跑 [Demucs](https://github.com/facebookresearch/demucs)，前端只负责播放。大致做法：

1. **安装 Demucs**（需要 Python 和 PyTorch，有 GPU 会快很多）：

   ```bash
   pip install demucs
   ```

2. **在 `server.js` 增加一个上传接口**，例如 `POST /api/separate`：
   - 把上传的文件保存到临时目录（限制文件大小，文件名用随机 ID，不要使用用户提供的文件名）。
   - 用 `child_process.execFile`（不要用拼接字符串的 `exec`）运行：

     ```bash
     # 4 轨：vocals / drums / bass / other
     demucs -n htdemucs -o out input.mp4
     # 6 轨：多出 guitar / piano
     demucs -n htdemucs_6s -o out input.mp4
     # 只要人声和伴奏两轨
     demucs --two-stems vocals -o out input.mp4
     ```

   - 输出在 `out/<模型名>/<文件名>/` 下，每条一个 WAV。接口返回这些 WAV 的地址（或打包返回），处理完删除临时文件。

3. **前端改动**：在 `public/js/app.js` 里把调用 `runSeparation` 的地方换成上传到 `/api/separate` 并拿回 WAV 地址，再交给 `player.js` 作为各音轨的来源。播放、同步、变速、循环部分不用改。

4. **Demucs 输出和按钮的对应关系**：

   | 按钮 | Demucs 来源 |
   | --- | --- |
   | 原曲 | 原文件，不变 |
   | 人声 | `vocals` |
   | 纯伴奏 | `drums + bass + other`（6 轨模型再加 `guitar + piano`），或 `--two-stems vocals` 的 `no_vocals` |
   | 鼓 | `drums` |
   | 贝斯 | `bass` |
   | 和声伴奏 | `other`（6 轨模型可用 `guitar + piano + other`） |
   | 额外打击乐 | Demucs 不单独输出，可继续用本项目的 DSP：对 `drums` 做 5 kHz 高通 |
   | 效果音 | Demucs 不单独输出，可对 `other` 用本项目的 DSP 取立体声两侧高频 |
   | 其他音效 | `other` 减去上面两条后的残余，或直接用 `other` |

注意：Demucs 处理一首歌在 CPU 上可能要几分钟，需要做任务排队和进度提示；服务对局域网以外开放时要加访问控制和上传大小限制。
